Mockup — Printer settings › Multimaterial, as actually implemented. The groups are the addition. This replaces an earlier, more ambitious version of this mockup; what changed and why is below, because the gap is worth knowing before anyone tries to close it.

What ships. A Sync from printer button reads the live topology (/multiace/api/state) and reports any divergence, so the machine can be the source of truth without Orca depending on it — the values stay in the preset and slicing still works offline. Per toolhead, Fed by (stock feeder, or an ACE unit with its slot count) and the ACE unit, which is greyed out on stock feeders because it means nothing there. A live-but-meaningless field is exactly what invited setting the unit instead of the capacity.

No magic numbers. Both fields are labelled dropdowns, so the stored value is never shown raw: 1 reads Stock feeder, 4 reads ACE – 4 slots, and unit 0 reads ACE 1 — matching every other surface, which is what stops a head wired to the first ACE being configured as unit 1. The lists stay open (i_enum_open), so an unusual slot count can still be typed.

This needed a fix to Orca itself, and it is worth knowing why. An earlier version of this mockup said named choices were not renderable, because i_enum_open was wired only for scalar options while these are coInts (one value per toolhead). That was half right: the gui_type already builds a Choice for any type, but five places in Field.cpp special-cased coInt without its vector twin. Four were cosmetic; the fifth, Choice::propagate_value, let a coInts value fall into the float branch, where boost::any_cast<double> threw on focus change — the exception escaped the wx handler and killed the app. Adding the missing cases is what makes this page possible, and it makes labelled dropdowns available to every per-extruder integer setting, not just these two.
